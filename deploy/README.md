# NegcesLab Infrastructure Deployment & Staging Guide

This folder contains all automated Infrastructure as Code (IaC) and Configuration Management code for setting up `negceslab` staging environments.

---

## Folder Architecture

```text
deploy/
├── provision-staging.sh       # Master 1-click script
├── ansible/                   # 100% Cloud-Agnostic OS Provisioning
│   ├── hosts                  # Inventory target file
│   ├── site.yml               # Main playbook (packages, Nginx, Podman, Seeding)
│   └── templates/             # Nginx vhost templates
└── terraform/                 # Cloud Hardware Provisioning
    ├── azure/                 # Azure VM, VNet, Security Group
    └── aws/                   # AWS EC2 Instance, Security Group
```

---

## Prerequisite Tools on Your Local Machine

Before executing Terraform or Ansible locally:
1. **Install Terraform**: `sudo apt install terraform`
2. **Install Ansible**: `sudo apt install ansible`
3. **Azure CLI**: `az login` (Authenticates Terraform with your Azure subscription)

## Step-by-Step Learning Walkthrough

### Step 1: Initialize and Plan Azure Infrastructure (Terraform)

```bash
# Navigate to the Azure Terraform directory
cd deploy/terraform/azure

# 1. Initialize Terraform (Downloads AzureRM provider)
terraform init

# 2. Preview the resources Terraform plans to create
terraform plan

# 3. Provision the Azure VM, IP, and Firewall
terraform apply
```

Upon completion, Terraform will output:
```text
public_ip_address = "20.46.241.165"
ssh_connect_command = "ssh negces-staging@20.46.241.165"
```

---

### Step 2: Configure System OS & App Stack (Ansible)

Now run Ansible against the IP address generated by Terraform:

```bash
# Navigate to the Ansible directory
cd ../../ansible

# Run the playbook against the provisioned IP
ansible-playbook -i "20.46.241.165," -u negces-staging site.yml
```

> **Note**: The comma after the IP address (`"20.46.241.165,"`) is intentional — it tells Ansible to treat the string as an inline host list.

---

### Step 3: Destroy Infrastructure When Finished Testing

When you are done testing for the day and want to tear down the instance to avoid incurring Azure charges:

```bash
cd deploy/terraform/azure

# Destroy all cloud resources created by Terraform
terraform destroy
```

---

## 1-Click Automated Script

Once you are comfortable with the step-by-step commands above, you can run the master script from the project root:

```bash
# For Azure
./deploy/provision-staging.sh azure

# For AWS
./deploy/provision-staging.sh aws
```
